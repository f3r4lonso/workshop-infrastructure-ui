# Interaction upgrade: decision and verification

Date: 2026-10-19. Status: partial delivery; acceptance pending.

## Scoped boundary decision

The owner's execution request authorizes the task's narrow extensions. The browser may explicitly save existing eligible canonical Markdown/TXT resources and send a selected text-only AI request. It remains outside session orchestration, arbitrary application code editing, terminal input injection, installation and task execution. Existing launch buttons remain separate from chat delivery.

Document access resolves IDs from the catalogue or a user-entered workspace-relative supported document path. Reject traversal, excluded components, hidden/configuration directories, links/junctions and outside-workspace paths. Editing is restricted to canonical shared agent/skill bodies, infra documentation/tasks and application README/docs; policy/configuration/source files remain protected. Save requires a SHA-256 version and serializes writes; conflicting changes retain the draft. Shared agent/skill identity and description fields cannot change through this editor, preserving catalogue metadata. Agent wrappers are regenerated by the fixed repository adapter command after a save; personal wrappers are also regenerated where applicable. No user content enters process arguments.

Reader integration imports the existing sibling reading assistant's standard-library extraction, cleanup, detection and local-only Ollama translator into the UI server. The browser uses the UI's same-origin authenticated API; no CORS or reader Origin exceptions. The existing speech chunk helper is served at a fixed same-origin URL and reused. No reader service needs to listen separately. Translation is explicit, original content remains separate, and cancellation is available for speech (translation is synchronous and cannot be cancelled). Files are bounded at the existing reader limit; translation keeps its existing 200,000-character limit, with rejection rather than truncation.

Text-only dispatch uses fixed client options, stdin and an isolated working directory. Registry capabilities identify documented public aliases separately from unknown account access. Existing console delivery is unavailable. A new isolated request is a concrete destination; any unsupported client transport is disabled with prerequisites. No automatic retries after ambiguous delivery.

## UX evidence and flows

The required UX researcher ran as a delegated fallback following `infra/agents/ux/ux-researcher.md`. This was a source/document audit, with no interviews, browser study or measured usability claims. Observed: navigation cleared search; only task status had a facet; categories were presentation headings; detail offered only copy/open; installation detection did not establish authentication; detail remounts would discard local component drafts.

Recommended flows now guide implementation: find/filter and return with state intact; explicitly load a document then translate locally and listen; load an eligible source, draft and explicitly Save with conflict detection; compose a message, inspect optional context and effective destination, then Send. Reading, editing and composition have distinct labels within the existing detail card. Drafts are keyed by resource and retained for navigation. Proposed usability benefits remain hypotheses until owner evaluation.

## Sequential agent chains
